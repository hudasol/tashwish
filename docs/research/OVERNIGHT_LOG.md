# Overnight log, 2026-10-16

A record of one unattended working session: what was done, what was found and what failed, in the order the work was done.

Rules followed throughout: the study window held out days stay closed (the held out validation was not run again), no frozen
threshold or detector behaviour was changed, and no raw ADS-B archive was written to git. Result numbers are in the committed
result files and generated pages named here; the only numbers typed in this log are test counts and command outcomes of the
session, which are not result files.

## A. Orientation

Done.

- Branch base: `phase5/review-fixes` (pull request 2, still open at the start of the session). The work of this session is on
  feature branches stacked on it.
- Tests: on this Windows machine, `python -m pytest -p no:warnings` gives 291 passed and 6 failed. All 6 failures are in
  `tests/test_release_build.py` and have one cause: `src/tashwish/release/build.py` reads a JSON file with `read_text()` and no
  encoding, so Python uses the Windows default code page and fails on a UTF-8 byte. With Python's UTF-8 mode
  (`PYTHONUTF8=1`) all 297 tests pass. CI runs on Linux, where UTF-8 is the default. The builder was not changed here (rule:
  only the changes the task needs); every later test run in this log uses `PYTHONUTF8=1`. `ruff check .` passes.
- Archive access: the adsb.lol `globe_history_2026` release asset for 2026-03-13 answered a HEAD request with status 200. A day
  inside the study window, already processed, was used on purpose, so that nothing about any day after 2026-03-13 was seen before
  the forward preregistration (item B) was committed.
- `TASHWISH_STATE_KEY` is not set in this environment (checked for the process, the user and the machine scope; the value was
  never printed). The frozen scoring path (`score_day_frozen` in `src/tashwish/operate/state.py`) keys aircraft addresses with
  this secret to match the persistent emitter list, and raises without it.

Consequences:

- Item C (backfill) is skipped, as instructed.
- Item D (forward chained validation) is blocked. Scoring new days against the frozen state needs the key. Rebuilding the
  persistent emitter list another way would be a workaround of the secret, so it was not done. What was done instead is to make
  D ready to run: the forward preregistration (item B) and the forward scorer are committed before any new day was downloaded,
  so the maintainer can run C and D as soon as the key is set (see item D below).

## B. Forward preregistration

Done, before any new data was looked at.

- `docs/PREDICTIONS_FORWARD.md` and its machine readable copy `results/forward/predictions_forward.json` (commit `7deb3f8`)
  preregister twelve predictions for the 30 days 2026-03-14 to 2026-04-12: regime persistence (F1 to F6), false coverage by
  traffic regime (F7, F8) and events per day (F9 to F12), each with a numeric pass criterion and a stated probability, plus three
  daily checks that locate where the forward run fails first.
- `scripts/score_forward.py` (commit `8ddabc6`) is the scorer, written before the data. It refuses study window days, rejects
  days not scored with the committed frozen state, and writes HIT or MISS with intervals, the Brier score and the first failing day.
  Its `calibrate` command wrote `results/forward/dev_calibration.json` from the 21 development days only. As a check of the
  scorer, its recomputed regime labels, en route units and tested degraded shares equal `results/regimes.csv` on all 21
  development days, and its per day false coverage equals the per day values in `results/dev/observed_coverage_summary.json`.
- Tests: 300 passed (`PYTHONUTF8=1`), including 3 new tests in `tests/test_score_forward.py` on synthetic days. `ruff check`
  and `ruff format --check` pass.
- Limitation: the predictions were written after the held out summaries of the study window were published in this repository,
  so they are informed by all 35 study days, not only by the development days. They are blind to every day after 2026-03-13.

## E. Science extras

Results are in `docs/research/SECONDARY_ANALYSES.md`, generated by `scripts/make_secondary_doc.py`.

1. Beta binomial sensitivity: done, on development days only (`scripts/beta_binomial_sensitivity.py`,
   `results/secondary/beta_binomial.json`). Before computing anything new, the binomial flags were rebuilt from the processed
   cell buckets and matched the committed events on every development day. Two apparent mismatches during this check were
   counting errors in the check itself (one jamming component appears in two `both` events; two separate events share a cell)
   and were fixed in the check, not in the data. Finding, OBSERVED: the flags on elevated days do not survive the measured
   overdispersion, and they already disappear at a correlation much smaller than the estimate; the flag on baseline days
   survives. Numbers and intervals are in the generated page.
2. More realistic injection variants: not done. They need the per sample points of the development days, which are not stored.
   The validation harness (which does not use the secret) fits the persistent emitter list from the points of all 21 development
   days, so every development day would have to be downloaded and parsed again. That did not fit the 60 minute budget and would be
   a heavy load on the volunteer archive.
3. Regime change and public sources: done as a source review. Four sources were fetched and are cited with their URLs. They
   report (reports, not ground truth) that several airspaces in the study box were closed to commercial traffic from
   28 February 2026 and that widespread GPS jamming affected ships in Gulf waters in early 2026. The first reduced traffic day
   and first elevated day already published for the study window fall at that time. That is consistent timing, not an established cause, and the page says so. Receiver network changes
   and aviation specific reports are UNVERIFIED. No attribution was written.

## G. Regeneration and adversarial review

Regeneration: the release and web data (`python -m tashwish.release.build --mode study_snapshot`), `docs/research/VALIDATION.md`,
`docs/research/PREDICTIONS_RESULTS.md`, `docs/research/REPORT.md` and the README status block were regenerated with the existing scripts. With no new
data, every regenerated file equals the committed one once the build time, the code commit stamp and line endings are normalised
(gzip files compared after decompression); the dataset version is unchanged. Nothing was committed, because the only differences
were new timestamps and Windows line endings: on Windows the generators write CRLF, which would put line ending noise into every
generated file. The generators were not changed; run them on Linux or in CI, or fix the newline handling in a separate change.

Adversarial review: a separate reviewer, without the reasoning of this session, read every change of the session against the
project rules. It reported no blocker, 7 major and 7 minor findings, and reproduced the three new result files byte for byte.
What was done with them:

- Fixed. The forward scorer did not pin the frozen state, labelled any day OBSERVED, could be run on a partial block, and let a
  day without covered units pass a daily check. The spec now pins the state hash and the preregistration time, and the scorer
  refuses another state or an incomplete block and rejects days ingested before the preregistration or not labelled observed.
  These amendments were made before any forward day was downloaded; no prediction, threshold or probability changed
  (`docs/PREDICTIONS_FORWARD.md`, section 7).
- Fixed. The test said to check that the spec and the document agree covered only identifiers and text; it now checks every row,
  pass criterion, probability, daily check and evaluability rule. Tests were added for the refusals, the five aircraft boundary,
  the first week subset and the F12 minimum.
- Fixed. `docs/research/SECONDARY_ANALYSES.md` had fixed sentences that would not follow a changed result, a degenerate interval for an
  underdispersed regime, and the phrase "too small" where the p values are miscalibrated in either direction. Readings are now
  derived from the result file.
- Fixed. The regime dates quoted in the source review are held out days. They are now quoted as results already published in
  the README and `docs/research/VALIDATION.md`, labelled as held out days, and not analysed further. Sources are described as reports,
  not as established facts, and a news item whose web address carried an actor framing was replaced by the analytics firm's own
  report.
- Fixed. Stale statements in `docs/LICENSING.md`, `docs/OPERATIONS.md` section 8, `docs/research/PROPOSAL.md`, the report and
  validation generators, and the README reading list.
- Fixed. The development day anchors gained day bootstrap intervals. Counts (label switches, failing days) are stated as counts
  without intervals.
- Not fixed. Archived copies or hashes of the fetched web pages are not stored: copying the pages into the repository would
  reproduce copyrighted text. Each source carries its address and retrieval date instead.
